# Production Runbook — Water Governance Hub

## Deployment order

1. Configure only browser-safe Supabase variables in Vercel:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY`
   - `VITE_SUPABASE_PROJECT_ID`
2. Keep `SUPABASE_SERVICE_ROLE_KEY`, secret API keys and AI gateway secrets server-side only.
3. Apply database migrations through the Supabase migration pipeline. Do not edit production tables manually.
4. Deploy the frontend only after the database migration has succeeded.
5. Do not run seed data against production.

## First administrator provisioning

Public self-bootstrap is intentionally disabled. Create the first account through Supabase Auth, then run the following as a trusted database administrator after replacing the placeholder UUID:

```sql
insert into public.profiles (id, full_name)
values ('00000000-0000-0000-0000-000000000000', 'Platform Administrator')
on conflict (id) do nothing;

insert into public.user_roles (user_id, role, tenant_id)
values ('00000000-0000-0000-0000-000000000000', 'super_admin', null)
on conflict (user_id, role) do update set tenant_id = excluded.tenant_id;
```

Do not put the administrator UUID, password, service-role key, or other credentials in source control.

## Database acceptance gate

Before promoting a migration:

```bash
supabase db reset
supabase test db
supabase db lint
```

The repository CI runs these checks together with TypeScript, ESLint and the production build.

## Security acceptance gate

- RLS enabled on every exposed application table.
- No `service_role`/secret key in browser bundles or committed `.env` files.
- Security-definer functions use a pinned `search_path` and have explicit `EXECUTE` grants.
- Tenant-child relationships are enforced by composite foreign keys.
- Meter readings and receipts are append-only from the browser.
- Paid invoice amounts cannot be silently recalculated.
- Receipt overpayments are rejected rather than discarded.
- The first super-admin cannot be claimed by an arbitrary signed-up user.

## Data governance

The platform treats meter readings, billing and receipts as auditable operational records. Integrity digests are generated by the database; they are not encryption and do not replace backups or database audit logging.

Recommended production controls include Point-in-Time Recovery, restricted production database access, regular backup/restore drills, and a staging environment that receives the same migrations before production. These practices align with Supabase's production guidance.
